## Purpose
Выполнять проектирование тестовой модели на основе проанализированных требований и сформированных задач для разработки.

Skill предназначен для проектирования тестовых сценариев, охватывающих позитивные и негативные сценарии, граничные условия,
с обеспечением трассируемости между требованиями, задачами разработки и тестовыми сценариями.

## Input
- результаты анализа требований из requirement_review.md:
- список задач для разработки из task_design.md
- ссылка на проект в Qase
- ссылка на связанные требования в Confluence
- ссылка на связанные задачи в Jira

Skill не может самостоятельно искать отсутствующие входные данные за пределами предоставленного контекста

## Procedure:
При проектировании тестовой модели необходимо:
- проанализировать каждое функциональное требование и определить необходимые тестовые сценарии
- для каждого требования спроектировать позитивные сценарии (штатное использование)
- для каждого требования спроектировать негативные сценарии (нарушение условий, некорректные данные)
- определить граничные условия и создать сценарии для их проверки
- обеспечить покрытие всех критических требований тестовыми сценариями
- для каждого сценария определить:
  - название, описывающее проверяемое условие
  - предусловия
  - шаги выполнения
  - ожидаемый результат
  - тип сценария (позитивный/негативный/граничный)
- обеспечить трассируемость: каждый сценарий должен быть связан с требованием и задачей
- сгруппировать сценарии по логическим модулям или функциям

## Rules
При проектировании тестовой модели необходимо соблюдать следующие правила:
- каждый сценарий должен иметь основание в проанализированных требованиях
- не выдумывать отсутствующие требования
- не выдавать предположения за подтвержденные требования
- не создавать сценарии на основе противоречивых требований (эскалировать)
- не создавать сценарии, если критически важная информация отсутствует (эскалировать)
- не дублировать проверки между сценариями
- обеспечивать уникальность проверок
- не создавать сценарии, не связанные с требованиями
- не изменять исходные требования
- не выполнять разработку или тестирование

## Output
Результат выполнения skill должен содержать:
- тестовую модель со списком сценариев, каждый из которых содержит:
  - название сценария
  - описание проверяемого условия
  - предусловия
  - шаги выполнения
  - ожидаемый результат
  - тип сценария (positive/negative/boundary)
  - связанное требование (Confluence)
  - связанная задача разработки (Jira)
- матрицу покрытия требований тестовыми сценариями
- список требований, не покрытых тестовыми сценариями, с указанием причины

Результат должен быть структурирован так, чтобы каждый сценарий мог быть напрямую перенесен в Qase

## Completion Criteria
Skill считается успешно выполненным, если:
- все критические требования покрыты тестовыми сценариями
- для каждого требования созданы позитивные и негативные сценарии
- граничные условия учтены
- нет дублирующихся проверок
- обеспечена трассируемость от сценариев к требованиям и задачам
- сценарии, которые не могут быть спроектированы, выделены с указанием причин
