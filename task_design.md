## Purpose
Выполнять формирование задач для команды разработки на основе проанализированных требований.

Skill предназначен для преобразования результатов анализа требований (из requirement_review.md) в структурированные
задачи с понятными целями, описаниями, критериями приемки и приоритетами.

## Input
- результаты анализа требований из requirement_review.md
- ссылка на проект в Jira
- ссылка на связанные требования в Confluence

Skill не может самостоятельно искать отсутствующие входные данные за пределами предоставленного контекста анализа
требований

## Procedure:
При формировании задач необходимо:
- сгруппировать функциональные требования по логическим блокам
- для каждого блока сформировать отдельную задачу
- для каждой задачи определить:
  - понятное название, описывающее цель
  - подробное описание функциональности
  - критерии приемки, основанные на требованиях
  - приоритет на основе бизнес-значения
  - зависимости от других задач
- обеспечить трассируемость: каждая задача должна иметь ссылку на исходные требования
- выявить задачи, которые не могут быть сформированы из-за неоднозначностей, противоречий или недостатка информации

## Rules
При формировании задач необходимо соблюдать следующие правила:
- каждая задача должна иметь основание в проанализированных требованиях
- не выдумывать отсутствующие требования
- не выдавать предположения за подтвержденные требования
- не создавать задачи, если требования содержат противоречия (эскалировать)
- не создавать задачи, если критически важная информация отсутствует (эскалировать)
- не дублировать проверки и функциональность между задачами
- не создавать задачи, не связанные с анализом требований
- не изменять исходные требования
- не выполнять разработку

## Output
Результат выполнения skill должен содержать:
- список задач для команды разработки с атрибутами:
  - название задачи
  - описание функциональности
  - критерии приемки
  - приоритет (P0/P1/P2/P3)
  - зависимости от других задач
  - ссылка на исходные требования (Confluence)
- список задач, которые не могут быть сформированы, с указанием причины
- матрицу трассируемости между задачами и требованиями

Результат должен быть структурирован так, чтобы каждая задача могла быть напрямую перенесена в Jira

## Completion Criteria
skill считается успешно выполненным, если:
- все проанализированные требования преобразованы в задачи
- каждая задача содержит название, описание, критерии приемки и приоритет
- нет дубликатов задач
- обеспечена трассируемость от задач к требованиям
- задачи, которые не могут быть сформированы, выделены с указанием причин
- выявленные неоднозначности, противоречия и недостатки информации учтены
